Chapter 1. Welcome! Making Friends with the Black Screen#

Modern bioinformatics is fundamentally intertwined with the command-line interface. While graphical user interfaces (GUIs) dominate personal computing and general office tasks, the sheer scale of genomic data necessitates an environment engineered for programmatic automation, stability, and high-performance computing. For the contemporary researcher or student entering the field, the "black screen" of the terminal is not an arcane relic of the computing past, but rather the most powerful and indispensable instrument in the modern scientific toolkit. Mastery of this environment is the first critical step toward reproducible, high-throughput biological data analysis.

What is Linux?#

At its core, Linux is an open-source operating system kernel. The kernel is the foundational software architecture that bridges the gap between the physical hardware of a computer—such as the central processing unit (CPU), random-access memory (RAM), and storage drives—and the software applications running on top of it. Originally developed by Linus Torvalds in 1991, the Linux kernel was subsequently combined with the GNU userland utilities to form a complete, functional operating system.

In the context of bioinformatics, Linux is the undisputed and absolute standard. Almost every major genomic alignment tool, variant caller, and transcriptomic assembler is developed natively for Linux environments. Because the Linux kernel is completely open-source, software developers and user communities worldwide have created hundreds of different "distributions" (often abbreviated as "distros") by packaging the core kernel with various desktop environments, package managers, and default software suites.

The vast Linux family tree primarily splits into two dominant, historical lineages: Red Hat and Debian.

Distribution Family Historical Origins & Philosophy Package Manager Primary Audience & Scientific Use Case
Red Hat (RHEL, Fedora, CentOS) Initiated by Red Hat Software in the mid-1990s, this lineage focuses heavily on corporate enterprise environments, strict stability, and commercial support. RPM / DNF / YUM Enterprise servers, large institutional data centres, and commercial computing clusters.
Debian (Ubuntu, Linux Mint) A volunteer-driven, community-supported effort emphasising free software principles, open access, and universal hardware compatibility. DPKG / APT Workstations, personal laptops, cloud computing instances, and academic bioinformatics research.

For a researcher or student entering the field of bioinformatics, Ubuntu—a distribution built directly upon the Debian architecture—is considered the absolute standard. Canonical, the corporate sponsor behind Ubuntu, releases Long Term Support (LTS) versions that guarantee years of stable, unbroken updates. Because of its massive user base, almost all bioinformatics software documentation and community-driven tutorials are explicitly written for Ubuntu. If a bioinformatician encounters an installation error with a specific genomic package, the vast Ubuntu community ensures that a solution is usually just a brief search away.

The Truth About the Terminal#

New users often use the terms "terminal," "shell," and "command line" interchangeably, but they represent distinct historical and technical concepts. Understanding this distinction demystifies the interface and provides vital context for how modern computing developed.

Historical Analogy: The Teletypewriter In the early days of computing, researchers interacted with massive, room-sized mainframe computers using an electromechanical device called a Teletypewriter (abbreviated as TTY). This device strongly resembled a physical typewriter connected to the mainframe via serial communication cables. A user would type a command, the mechanical keys would physically strike paper to record the input, and the mainframe's response would be typed out onto the exact same continuous roll of paper.

Today, physical TTY devices are obsolete, entirely replaced by digital monitors and software abstractions. When a researcher opens a "terminal" window on a modern desktop, they are actually opening a Terminal Emulator. This software visually mimics the behaviour of the ancient mechanical TTYs on a digital screen, creating what the Linux kernel refers to as a Pseudo-Terminal (PTY).

The Terminal Emulator simply acts as the physical hardware substitute—it catches keyboard strokes, renders fonts, and displays text. It possesses no computing logic of its own. The actual programme that interprets the typed commands, evaluates them, and executes the underlying code is called the Shell. Therefore, the terminal is merely the viewing window, while the shell is the active engine running inside it.

Hands-On Exercises#

  1. Identify Your System: Open a terminal on any Linux system (or WSL2) and run uname -a. Document the kernel version and architecture displayed.

  2. Explore Distribution Information: Run cat /etc/os-release to view details about your Linux distribution. Note the NAME, VERSION, and ID fields.

  3. Terminal vs Shell Distinction: Run echo $SHELL to identify which shell you are using, then run echo $TERM to see your terminal emulator type.

Key Takeaways#

  • Linux is an open-source kernel that forms the foundation of bioinformatics computing infrastructure.
  • Ubuntu (Debian family) is the recommended distribution for bioinformatics beginners due to extensive community support.
  • The terminal is the visual interface; the shell (typically Bash) is the interpreter that executes commands.
  • Understanding these fundamentals provides essential context for all subsequent chapters.

Chapter 2. Planting Linux in Your Windows: WSL#

Most institutional laptops, academic workstations, and personal computers are provisioned with Microsoft Windows. Historically, accessing a native, high-performance Linux environment for bioinformatics on a Windows machine presented significant friction and workflow bottlenecks.

The Traditional Pain#

Before modern virtualisation technologies matured, researchers generally relied on two options to access Linux, both of which were fraught with severe drawbacks:

  1. Dual-Booting: This method required carving out a permanent, fixed partition on the computer's hard drive and installing a Linux distribution alongside Windows. While it offered native hardware performance, it required a complete system reboot to switch between environments. A researcher could not computationally align a .bam file in Linux while simultaneously attending a virtual lab meeting on Microsoft Teams, reading a PDF publication, or writing a manuscript in Microsoft Word. This context-switching severely hampered productivity.

  2. Heavy Virtual Machines (VMs): Software platforms like VirtualBox or VMware allowed users to run a full Linux operating system inside a windowed application on the Windows desktop. However, traditional VMs were exceptionally "heavy." They required pre-allocating a fixed, immutable chunk of system RAM and CPU cores. If 16GB of RAM was allocated to the VM, Windows instantly lost access to that memory, regardless of whether the Linux environment was actively computing genomics data or merely sitting idle. Furthermore, sharing files between the Windows host and the Linux guest was notoriously slow, cumbersome, and prone to permission errors.

Why WSL2?#

Microsoft resolved these historical pain points with the introduction of the Windows Subsystem for Linux (WSL), and more importantly, its heavily revised second iteration: WSL2. Because the majority of researchers use Windows for daily administrative and academic tasks, WSL2 allows them to operate a genuine Linux environment without ever leaving the Windows ecosystem.

WSL2 represents a fundamental paradigm shift in OS integration. Unlike traditional heavy VMs, WSL2 runs a real Linux kernel—built by Microsoft from the stable kernel.org branches—inside a highly optimised, lightweight utility virtual machine.

WSL2 solves the heavy VM problem through an ingenious dynamic memory model. It boots in seconds, dynamically scales its memory footprint based on active computational workloads, and releases RAM back to Windows the moment the bioinformatics pipeline finishes executing. Most critically for researchers, WSL2 strongly emphasises seamless file sharing. Utilising the 9P file system protocol (originally from Plan 9) and VSOCK communication channels, users can access their entire Windows C:\ drive directly from the Linux terminal. This allows a researcher to download sequencing data via a Windows web browser and instantly process it via Linux command-line tools without moving files between virtual drives.

Setup Guide#

Installing WSL2 has been significantly streamlined by Microsoft to require only a single command. The user simply needs to open the native Windows PowerShell as an Administrator and execute:

wsl --install

This specific command automatically downloads the required Hyper-V virtualisation components, installs the true Linux kernel, and sets Ubuntu as the default distribution. Following a system reboot, the user possesses a fully functional Ubuntu ecosystem embedded within Windows.

To drastically enhance the user experience, it is highly recommended to install the Windows Terminal application from the Microsoft Store. Windows Terminal serves as a highly customisable, multi-tabbed user interface wrapper that allows researchers to run Windows PowerShell, Command Prompt, and the Ubuntu WSL2 shell side-by-side. It supports deep UI customisation, including aesthetic colour schemes, specialised font ligatures tailored for reading code, and custom key bindings, transforming the sterile default prompt into an inviting, professional bioinformatics workspace.

Advanced Configuration: .wslconfig#

For bioinformatics workloads involving large genomic datasets, fine-tuning WSL2's resource allocation is essential. The .wslconfig file, located at C:\Users\<YourUsername>\.wslconfig, allows global configuration of all WSL2 distributions.

Create or edit this file in Windows:

# Settings apply across all Linux distros running on WSL 2
[wsl2]
# Limits VM memory to 16 GB (adjust based on your system)
memory=16GB

# Sets the VM to use 8 virtual processors
processors=8

# Sets amount of swap storage space
swap=8GB

# Sets swapfile path location
swapFile=C:\\temp\\wsl-swap.vhdx

# Disable page reporting so WSL retains all allocated memory
pageReporting=false

# Turn on default connection to bind WSL 2 localhost to Windows localhost
localhostForwarding=true

# Nested virtualization (required for Docker-in-WSL)
nestedVirtualization=true

After modifying .wslconfig, restart WSL2 for changes to take effect:

wsl --shutdown

GUI Application Support: WSLg#

WSL2 now includes WSLg (WSL GUI), enabling Linux graphical applications to run seamlessly alongside Windows applications. This is invaluable for bioinformatics tools with graphical interfaces such as IGV (Integrative Genomics Viewer), R Studio, or sequence visualisation tools.

WSLg is automatically included in Windows 11 and available for Windows 10 (build 19044+). To verify WSLg is working:

Chapter 3. The Conductor of the Terminal: The Bash Shell#

As established in the historical overview, the terminal emulator is just the visual interface; the true power lies in the shell. The shell acts as the conductor, taking human-readable text commands, translating them into lower-level system calls, and orchestrating the computer's kernel and hardware to execute complex computational tasks.

What is a Shell?#

The shell is fundamentally a command-line interpreter. While several modern shells exist—such as Zsh (Z Shell) and Fish (Friendly Interactive Shell)—the absolute, undisputed standard for bioinformatics is the Bash (Bourne Again SHell) environment.

While Zsh and Fish offer aesthetic auto-completion and syntax highlighting out-of-the-box, Bash is mandated for a critical scientific reason: reproducibility. The bedrock of the scientific method requires that an RNA-seq pipeline developed in a laboratory in Tokyo executes identically on a High-Performance Computing (HPC) cluster in London. Because Bash is the default shell on nearly every Linux server globally and adheres strictly to POSIX (Portable Operating System Interface) standards, scripts written in Bash are universally portable. Bioinformaticians prioritise Bash over aesthetic shells to ensure their complex analytical pipelines do not break due to incompatible shell dialects.

The File System Tree & Paths#

To command the Bash shell effectively, a user must understand how Linux organises data. Unlike Windows, which maps physical storage devices to arbitrary drive letters (e.g., C:\, D:), Linux unifies all storage, network drives, and peripherals under a single, inverted hierarchical tree. This tree begins at the ultimate top-level "root" directory, denoted simply by a forward slash (/).

Analogy: Absolute vs. Relative Paths

Consider the precise physical address: "2066 Seobu-ro, Jangan-gu, Suwon-si, Gyeonggi-do, Republic of Korea".

An Absolute Path is akin to providing this full, unedited postal address. No matter where someone currently stands in the world, this absolute address points unambiguously to a single physical location. In the Linux file system, an absolute path always begins at the root (/).

A Relative Path is akin to providing local directions based entirely on one's current physical location. If a person is already standing inside the Jangan-gu district office, they do not need the full national postal address; they simply need relative directions like "walk out the front door, turn left, and cross the street." In Linux, a relative path navigates from the user's Current Working Directory (CWD) and never begins with a slash. It heavily utilises the .. notation, which explicitly means "move up one parent directory."

Chapter 4. Linux Survival Kit: Core Commands and System Tools#

The Linux command line provides a vast, highly modular vocabulary of utilities. Most of these foundational commands belong to the GNU Coreutils, a meticulously maintained package of standard text, file, and directory manipulation tools developed by the GNU Project, which are frequently combined with essential system monitoring tools. Mastering this survival kit allows a bioinformatician to manipulate vast datasets effortlessly, without relying on graphical interfaces that fail under heavy data loads.

Directory Navigation & Creation#

Before manipulating genomic files, one must learn to move precisely through the directory tree and construct scaffolding for analytical projects.

  • pwd (Print Working Directory): It is incredibly easy to get lost in the terminal hierarchy. Executing pwd queries the shell to print out the absolute path of the user's current location, providing immediate geographical orientation.

  • mkdir (Make Directory): Used to create new folders. For bioinformatics projects, creating structured, nested directories is crucial for project organisation. The -p (parents) flag forces the system to create the entire nested path at once without complaining or failing if the intermediate parent directories do not yet exist.

mkdir -p rna_seq_project/raw_data rna_seq_project/results rna_seq_project/scripts
  • cd (Change Directory): Moves the user's current working directory to a new location.
cd rna_seq_project/raw_data
  • ls (List): Lists the contents of a directory. By default, it outputs simple names, but in genomics, file sizes are immense and require careful tracking. The flags -l (long format) and -h (human-readable) are essential for checking the file sizes of compressed sequencing reads, transforming raw byte counts into Megabytes and Gigabytes.
ls -lh *.fastq.gz

Example Output:

-rw-r--r-- 1 researcher researcher 4.2G Oct 12 10:14 sampleA_R1.fastq.gz
-rw-r--r-- 1 researcher researcher 4.5G Oct 12 10:20 sampleA_R2.fastq.gz
-rw-r--r-- 1 researcher researcher 4.1G Oct 12 10:25 sampleB_R1.fastq.gz
-rw-r--r-- 1 researcher researcher 4.4G Oct 12 10:31 sampleB_R2.fastq.gz

File Management#

Moving, copying, and deleting files are actions performed thousands of times during a project lifecycle. Precision is critical, as the command line lacks the safety nets found in graphical interfaces.

  • cp (Copy): Duplicates a file. The following example demonstrates copying a human reference genome from a shared institutional directory to the current directory (denoted by the . shorthand).
cp /shared/reference/GRCh38.fa ./
  • mv (Move): Used to move a file from one location to another, or to rename it in place.
mv sampleA_R1.fastq raw_data/
  • rm (Remove): Deletes files. Warning: Linux does not have a "Recycle Bin." Once a file is removed via rm, its inode pointer is permanently deleted. The -r (recursive) and -f (force) flags bypass safety checks to delete whole folders entirely. Extreme caution is advised.
rm -rf tmp_alignment_files/
  • touch: Creates an empty file or updates the modification timestamp of an existing one.
touch pipeline_log.txt
  • tee: Takes a data stream and splits it in two simultaneous directions—outputting to the screen and saving to a file.
bash run_bwa.sh | tee alignment_log.txt

Viewing Giants#

Opening a simple .txt file in a GUI editor like Microsoft Notepad is trivial. However, attempting to double-click and open an uncompressed 50GB .fastq file will immediately exhaust a standard computer's RAM. Command-line tools gracefully bypass this limitation by streaming text, only loading the immediately visible bytes into memory.

  • head / tail: Extracts the top or bottom lines of a file. In a FASTQ file, a single biological sequencing read is strictly composed of exactly 4 lines. To view exactly one sequencing read:
head -n 4 sample1.fastq
  • cat, more, less: cat concatenates an entire file to the screen. less is the standard terminal pager; it safely loads a fraction of a giant file, allowing scrolling without crashing the system.
less sample1.sam

Text Processing Tools for Bioinformatics#

Bioinformatics involves extensive manipulation of text-based data formats. The following tools are indispensable for processing genomic data files.

wc (Word Count)#

Counts lines, words, and characters in files. Essential for quickly verifying file integrity and read counts.

# Count lines in a FASTQ file (divide by 4 for read count)
wc -l sample.fastq

# Count reads in a FASTQ file
echo $(( $(wc -l < sample.fastq) / 4 ))

sort#

Sorts lines of text files. Critical for preparing data for downstream tools that require sorted input.

# Sort a BED file by chromosome and position
sort -k1,1 -k2,2n peaks.bed > peaks_sorted.bed

# Sort numerically by the fifth column (e.g., p-values)
sort -k5,5n results.txt > results_sorted.txt

# Sort and remove duplicates
sort -u gene_list.txt > unique_genes.txt
sort Flag Function
-k Sort by specific column(s)
-n Numeric sort
-r Reverse order
-u Unique (remove duplicates)
-t Specify field delimiter

uniq#

Reports or filters out repeated lines. Must be used on sorted input.

# Count occurrences of each chromosome in a BED file
cut -f1 peaks.bed | sort | uniq -c

# Find duplicate gene names
sort gene_list.txt | uniq -d

# Keep only unique entries
sort gene_list.txt | uniq -u

cut#

Extracts specific columns from delimited files.

# Extract gene names (column 4) from a BED file
cut -f4 genes.bed

# Extract multiple columns from a tab-delimited file
cut -f1,3,5 data.tsv

# Use comma as delimiter
cut -d',' -f2 data.csv

sed (Stream Editor)#

Performs text transformations on an input stream. Invaluable for batch editing files.

# Replace all occurrences of 'chr' prefix (UCSC to Ensembl format)
sed 's/^chr//' ucsc_file.bed > ensembl_file.bed

# Add 'chr' prefix to chromosome names
sed 's/^/chr/' ensembl_file.bed > ucsc_file.bed

# Delete header lines starting with '#'
sed '/^#/d' file.vcf > noheader.vcf

# Replace tabs with commas
sed 's/\t/,/g' data.tsv > data.csv

# Edit file in place (use with caution)
sed -i 's/old/new/g' file.txt
sed Pattern Function
s/old/new/ Substitute first occurrence
s/old/new/g Substitute all occurrences (global)
/pattern/d Delete lines matching pattern
-i Edit file in place
-n Suppress automatic printing

awk#

A powerful pattern-scanning and processing language. Extremely useful for column-based operations on tabular bioinformatics data.

# Print specific columns from a SAM file (read name and mapping quality)
awk '{print $1, $5}' aligned.sam

# Filter BED file for regions longer than 1000bp
awk '$3 - $2 > 1000' peaks.bed > long_peaks.bed

# Calculate average of a column (e.g., coverage depth)
awk '{sum += $4; count++} END {print sum/count}' coverage.bed

# Filter VCF for variants with quality > 30
awk '$6 > 30' variants.vcf > high_quality.vcf

# Convert FASTQ to FASTA
awk 'NR%4==1 {print ">"substr($0,2)} NR%4==2 {print}' reads.fastq > reads.fasta

# Sum total bases in column 3 minus column 2 (total peak coverage)
awk '{sum += $3 - $2} END {print sum}' peaks.bed
awk Feature Example Function
$1, $2, ... print $1 Access columns by number
$NF print $NF Last column
NR NR > 1 Row number (skip header)
NF NF == 5 Number of fields
BEGIN/END END {print sum} Execute before/after processing
-F -F'\t' Set field delimiter

Combining Tools: Practical Examples#

# Count reads per chromosome from a BAM file
samtools view aligned.bam | cut -f3 | sort | uniq -c | sort -rn

# Extract unique gene names from a GTF file
awk '$3 == "gene" {print $10}' annotation.gtf | tr -d '";' | sort -u > genes.txt

# Find the top 10 most frequently mutated genes
cut -f1 mutations.txt | sort | uniq -c | sort -rn | head -10

# Calculate total mapped bases from a BED file

Compression and Archiving#

Bioinformatics data is massive. A single whole-genome sequencing run can produce hundreds of gigabytes of raw data. Compression is not optional—it is essential for storage, transfer, and processing.

gzip / gunzip#

The most common compression format in bioinformatics. FASTQ, VCF, and many other files are routinely gzip-compressed.

# Compress a file (original is replaced with .gz version)
gzip sample.fastq

# Decompress
gunzip sample.fastq.gz

# Keep original file while compressing
gzip -k sample.fastq

# View compressed file without decompressing
zcat sample.fastq.gz | head -n 4

# Compress with maximum compression (slower)
gzip -9 sample.fastq

Pro tip: Many bioinformatics tools (BWA, STAR, samtools) can read .gz files directly—no need to decompress first!

tar (Tape Archive)#

Bundles multiple files/directories into a single archive. Often combined with gzip compression.

# Create a compressed archive (.tar.gz or .tgz)
tar -czvf project_backup.tar.gz project_folder/

# Extract a compressed archive
tar -xzvf project_backup.tar.gz

# List contents without extracting
tar -tzvf project_backup.tar.gz

# Extract to specific directory
tar -xzvf archive.tar.gz -C /destination/path/
Flag Meaning
-c Create archive
-x Extract archive
-z Use gzip compression
-v Verbose (show progress)
-f Specify filename
-t List contents

Understanding .bashrc vs .bash_profile#

New users often confuse these two configuration files. The distinction relates to how shells are started:

File When Executed Typical Use
~/.bash_profile Login shells only (SSH login, console login) One-time session setup
~/.bashrc Interactive non-login shells (new terminal window) Aliases, PATH, prompt customisation

The Problem: On most systems, opening a new terminal runs .bashrc, but SSH connections run .bash_profile. This can cause inconsistent environments.

The Solution: Add this to your ~/.bash_profile to ensure .bashrc always runs:

# ~/.bash_profile
if [ -f ~/.bashrc ]; then
    source ~/.bashrc
fi

WSL2 Note: WSL2 terminals typically run .bashrc directly, but adding the above to .bash_profile ensures consistency when connecting via SSH.

Best Practice: Put all your customisations (PATH, aliases, environment variables) in ~/.bashrc, and use the above snippet in ~/.bash_profile.

Understanding Package Managers: pip vs Conda#

Python users often encounter two package managers: pip and Conda. Understanding their differences is crucial for bioinformatics work.

What is pip?#

pip is Python's official package manager. It installs packages from PyPI (Python Package Index).

pip install numpy pandas matplotlib
pip install -r requirements.txt

What is Conda?#

conda is a language-agnostic package and environment manager. It handles not just Python, but also R, C libraries, and compiled binaries.

conda install numpy pandas samtools bwa

Key Differences#

Aspect pip Conda
Scope Python packages only Any language (Python, R, C, etc.)
Package source PyPI (400,000+ packages) Conda channels (fewer, but curated)
Dependencies Python dependencies only All dependencies including system libraries
Binary handling Often requires compilation Pre-compiled binaries
Environment management Needs venv separately Built-in environments
Bioinformatics tools Limited Excellent via Bioconda

Why Conda is Preferred for Bioinformatics#

Bioinformatics tools often have complex dependencies:

samtools requires:
├── htslib (C library)
├── zlib (compression)
├── libbz2 (compression)
└── libcurl (network)
  • pip: Cannot install C libraries. You must manually install system dependencies.
  • Conda: Installs everything automatically, including compiled C code.

Using pip Inside Conda Environments#

Sometimes a package exists only on PyPI. You can safely use pip within a conda environment:

1. Install conda packages first
2. Install pip packages last
3. Never mix in the other direction

#!/bin/bash

# Function library for bioinformatics

log_message() {
    local level=$1
    local message=$2
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] [$level] $message"
}

check_file() {
    local file=$1
    if [ ! -f "$file" ]; then
        log_message "ERROR" "File not found: $file"
        return 1
    fi
}

run_fastqc() {
    local input=$1
    local output_dir=${2:-"qc_results"}

    check_file "$input" || return 1
    mkdir -p "$output_dir"

    log_message "INFO" "Running FastQC on $input"
    fastqc "$input" -o "$output_dir"
    log_message "INFO" "FastQC complete"
}

# Main script
log_message "INFO" "Starting analysis"
for fq in *.fastq.gz; do
    run_fastqc "$fq"
done

Part 0: Setup - Generate Simulation Data

Before starting the assignment, create your test FASTQ files using the script below.

Step 0.1: Create the Data Generator Script

Create a file named generate_fastq.sh with the following content:

#!/bin/bash
# FASTQ Simulation Data Generator
# Generates realistic FASTQ files for learning purposes

set -euo pipefail

# Default parameters
NUM_READS=${1:-10000}
READ_LENGTH=${2:-100}
OUTPUT_PREFIX=${3:-"sample"}

# Function to generate random DNA sequence
generate_sequence() {
    local length=$1
    cat /dev/urandom | tr -dc 'ATCG' | head -c "$length"
}

# Function to generate quality scores (Phred+33)
generate_quality() {
    local length=$1
    # Generate scores between 20-40 (good quality range)
    cat /dev/urandom | tr -dc 'IJKLMNOPQRSTUVWXYZ[\]^_' | head -c "$length"
}

# Main generation loop
echo "Generating $NUM_READS reads of length $READ_LENGTH..."

for ((i=1; i<=NUM_READS; i++)); do
    # Vary read length slightly (90-100% of target)
    variation=$((RANDOM % 11))
    actual_length=$((READ_LENGTH - variation))

    seq=$(generate_sequence $actual_length)
    qual=$(generate_quality $actual_length)

    echo "@${OUTPUT_PREFIX}_read_${i} length=${actual_length}"
    echo "$seq"
    echo "+"
    echo "$qual"
done

echo "Generation complete!" >&2

Step 0.2: Generate Sample Files

# Make the script executable
chmod +x generate_fastq.sh

# Generate two sample files (simulating paired-end reads)
./generate_fastq.sh 10000 100 "sample_A" > sample_A.fastq
./generate_fastq.sh 10000 100 "sample_B" > sample_B.fastq
./generate_fastq.sh 5000 75 "sample_C" > sample_C.fastq

# Compress the files (as you would receive them from a sequencing facility)
gzip sample_A.fastq sample_B.fastq sample_C.fastq

You should now have: sample_A.fastq.gz, sample_B.fastq.gz, sample_C.fastq.gz

Useful Command Patterns

# Process every 4th line starting from line N
awk 'NR % 4 == N'

# Count unique values
sort | uniq -c | sort -rn

# Calculate sum/average in awk
awk '{sum += $1} END {print sum/NR}'

# Loop through files
for file in *.fastq; do
    echo "Processing $file"
done

Common Mistakes to Avoid

  1. Forgetting to handle compressed files - Use zcat for .gz files
  2. Off-by-one errors in line counting - FASTQ has 4 lines per read
  3. Not quoting variables - Always use "$variable"
  4. Hardcoding paths - Use variables for flexibility
